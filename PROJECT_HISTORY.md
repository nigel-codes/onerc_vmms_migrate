# Project history import

Projects retain their document names and use the destination Company as the legal entity. The source Company maps to the project Geo Node. History uses an explicit override where an operational scope differs from a person's affiliation. On kenyaclone, the eight source region labels resolve to existing regions. The HQ history override resolves to the national node. The people branch mapping continues to resolve HQ to Nairobi county.

Projects, Tasks and TORs use the mapped source owner when the User is available. A missing owner generates a warning and uses Administrator. This supports the portal's Only mine filter. Opening the project also requires the destination role and Geo Assignment. Project User rows remain in the archive as requested. Deployment assignments carry the volunteer participation records. Project templates, the inactive workflow field, the old legal company and shared/deleted log comments also remain in source history.

The reference phase prepares the exact Project Type values and reports `health` and `DPR 146` for review. Departments resolve using the destination Company's abbreviation and its Department records. Unresolved optional links produce history warnings. Project date values are converted explicitly. File-only TORs link to the imported Project, with a warning if a recorded project link cannot resolve.

## Naming continuity

The normal loaders reserve counters for compatible destination names. They use the captured source counter, including numbers reserved for records since deleted, and the highest preserved number. The database update preserves any higher destination counter. Existing history records also reserve their counters on retry. Installed naming rules keep their definitions and receive the corresponding source counter when their prefixes and digit widths match.

| Preserved names | Destination naming behavior |
| --- | --- |
| Project, Task | `PROJ-` and the matching `TASK-YYYY-` counters |
| Event Booking, Event | Matching `B` and `EV` counters |
| Buzz Event, Event Ticket Type | MariaDB native numeric sequences advance past the highest preserved ID |
| Event Category, Event Host, Event Venue | Prompt names with no series counter |
| Event Ticket, Event Check In | Hash or default hash naming |
| VMMS Availability Schedule | Name comes from the mapped volunteer |
| Volunteer, Member, Membership | Matching installed series and naming rules advance during the people phase |
| Derived deployment containers | Reserved `legacy-assignment-` names outside the destination deployment series |
| Other historical records generated by the destination | Native naming consumes its own counter when the DocType uses one |

Source tabSeries and naming-rule counters are present in continuity captures. The capture lacks a separate source MariaDB sequence watermark, so numeric sequence continuity uses the highest preserved ID. The live and persistent test paths advance these sequences. Rollback rehearsals report numeric floors and keep the sequence untouched because MariaDB sequences survive transaction rollback. [MariaDB SETVAL documentation](https://mariadb.com/docs/server/reference/sql-structure/sequences/sequence-functions/setval)

Automatic series matching covers the literal and date parts used by these installed DocTypes. Changed naming schemes or custom naming expressions require review before changing their definitions. The naming planner can inspect existing people rule differences.

## Local rehearsal using oldprod.localhost

The rehearsal on kenyaclone imported 71 Projects and 57 Tasks in a rollback transaction. Of those Tasks, 46 link to projects. It imported all 54 structured TORs. The scoped reference setup also created 88 of 91 deployments, with three held by absent coordinator accounts. All 51 file-only TORs created by those deployments linked to their projects.

Project `PROJ-0002` resolved to the national node and `PROJ-0005` to Coast Region. The records retained 49 project types and 11 departments. Three projects referenced an unavailable department and generated warnings. Sixty-seven projects retained their owner. Four generated an owner fallback warning. One original creator with a temporarily staged Projects User role and geographic scope opened the project from Only mine. Staff role and scope migration still requires separate reconciliation.

The captured counters were `PROJ-` 106, `TASK-2025-` 18 and `TASK-2026-` 56. The portal create API issued `PROJ-0107`. Replaying the Project and Task load recognized all 128 existing records and kept the counters at their required floors. A subsequent retry kept the raised `PROJ-` counter at 107. The transaction rolled back all temporary records and counter changes.
